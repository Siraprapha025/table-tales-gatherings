# แก้ปัญหาสร้างงานแล้วขึ้นข้อผิดพลาดภายในระบบ

ตรวจวันที่ 24 ตุลาคม 2569: backend ที่ตั้งไว้ในโปรเจกต์ตอบ `42703: column events.bank_name does not exist` จากคำขออ่านโครงสร้างแบบ limit=0 ไม่ได้ดึงข้อมูลลูกค้าหรือแก้ฐานข้อมูล

สาเหตุที่ยืนยันได้คือฐานข้อมูลยังไม่มีคอลัมน์ธนาคารที่โค้ดใหม่ส่งไป ไม่ใช่ข้อมูลในแบบฟอร์มไม่ครบ

## ทำใน Lovable ครั้งเดียว

1. เปิดโปรเจกต์เดิมใน Lovable แล้วไป More → Database → Manage → SQL editor (บางหน้าจออาจอยู่ภายใต้ Cloud)
2. ตรวจว่าเป็นฐานข้อมูลของโปรเจกต์นี้ และเก็บสำรองก่อนติดตั้ง
3. เปิด `docs/setup-manual-payments.sql` จากโปรเจกต์ หรือไฟล์ที่แนบในแชต คัดลอกข้อความทั้งไฟล์
4. วางใน SQL editor แล้วกด Run หาก Lovable ให้ยืนยันการเปลี่ยนโครงสร้าง ให้อ่านรายการแล้วอนุมัติเมื่อฐานข้อมูลถูกต้อง
5. เมื่อสำเร็จจะแสดง “เพิ่มระบบรับเงินเรียบร้อยแล้ว กลับไปลองสร้างงานในเว็บได้”
6. กลับหน้าสร้างงานแล้วลองยืนยันบันทึกอีกครั้ง หากยังผิดพลาด ให้คัดลอกข้อความ error กลับมา

ไฟล์นี้รวมส่วน booking_safety และ manual_payments ใช้กับฐานข้อมูลเดิมที่ยังไม่มีคอลัมน์รับเงินเท่านั้น ไม่ต้องรัน baseline หรือ migration สองไฟล์นั้นซ้ำหลังติดตั้งชุดนี้

การเพิ่มทั้งหมดอยู่ใน transaction ถ้ามีคำสั่งล้มเหลวจะไม่เก็บการเพิ่มบางส่วน คำสั่งตรวจล่วงหน้าจะหยุดหากมีส่วนรับเงินอยู่แล้วหรือไม่พบตารางหลัก ห้ามลบตารางเพื่อแก้ข้อความว่ามีข้อมูลเดิม ให้ส่งข้อผิดพลาดมาตรวจแทน

## โค้ดที่แก้เพิ่ม

- คงหน้าสรุปไว้ระหว่างบันทึก แสดง “กำลังบันทึก…” และป้องกันการกดซ้ำขณะส่งคำขอ
- หากบันทึกล้มเหลว แสดงสาเหตุในหน้าสรุป พร้อมเก็บข้อมูลที่กรอกไว้
- หากเขียนฐานข้อมูลสำเร็จแต่โหลดหน้ารายการล้มเหลว จะแจ้งว่า “บันทึกแล้ว” เพื่อไม่ให้สร้างงานซ้ำ
- ข้อผิดพลาดตาราง/คอลัมน์/ฟังก์ชันหาย แสดงข้อความว่าฐานข้อมูลยังไม่พร้อมแทน error ทั่วไป

ไฟล์ SQL ยังไม่ได้ถูกสั่งรันบนฐานข้อมูลจริงจากแชตนี้ ไม่มีการ Commit, Push หรือ Deploy แทนผู้ใช้
